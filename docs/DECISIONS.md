# Architecture & Fail-Closed Decisions (`docs/DECISIONS.md`)

1. **Package Layout:** Place Person B's new service-layer package at `src/identity_keys/` (matching the repository's `src/` module layout) and expose `track4_service.py` at the repository root as required by Track 4 Adapter Contract v1. Preserve all existing `src/crypto/`, `src/audit/`, `src/detector/`, and `src/node/` files untouched.
2. **Real Cryptography (No Mocks):** Use `cryptography` (`Ed25519` for device identity & API bearer tokens; `AES-256-GCM` for key wrapping; `SHA-256` for fingerprints) and `pqcrypto` (`ML-KEM-768` for `protected_read` interoperability). Never use mock crypto fallbacks.
3. **Database & Dual-Dialect Triggers:** Target PostgreSQL 16 in `docker-compose.yml` and Alembic (`ENUM`, `JSONB`, `BIGSERIAL`, partial unique index, PL/pgSQL triggers). Support SQLite in `alembic` / `models.py` with equivalent `CHECK`, `UNIQUE`, partial unique index, and `RAISE(ABORT, ...)` triggers so local tests without a running Postgres daemon still exercise real DB-enforced constraints and `upgrade`/`downgrade`.
4. **Fail-Closed Authorization:** `AuthzService.authorize()` wraps all DB/state access in `try/except` and returns `AuthzDecision(allowed=False, reason_code="STATE_UNAVAILABLE", ...)` on any DB error, missing state, or stale cache beyond `MAX_CACHE_STALENESS_MS`.
5. **Authenticated Context:** API routes verify a short-lived Ed25519-signed bearer token (`device_id`, `user_id`, `exp`, `jti`) issued by `verify_identity`; `actor_id` is never read from request body text.
6. **Transactional Audit Outbox:** `AuditEmitter` writes to `audit_outbox` inside the same DB transaction as the state change; `AuditDispatcher` forwards records to `src/audit/logger.py` (`AuditLogger`) preserving the hash chain and newline sanitization.
7. **Uncommitted Rotation Recovery Policy:** On node startup/recovery, rotations left in `STARTED`, `PENDING_PERSISTED`, or `VERIFIED` without a `COMMITTED` record are **aborted and cleaned up** (`rotations.status = 'ABORTED'`, pending key transitioned to `RETIRED` with wrapped private material wiped, and `rotation.recovered` audit event emitted). Callers may still re-initiate with a fresh `idempotency_key`.
8. **Strict Grace Cutoff:** `is_key_acceptable()` enforces `now < grace_until` strictly at verification time with zero server-side clock-skew allowance; sweeper `GRACE -> RETIRED` is for hygiene only and never relied upon for security enforcement.
